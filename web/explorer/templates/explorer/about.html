🌸 DMI / SMBIOS Hardware Explorer
Operating Systems Course Project
C Django Docker SMBIOS WMI Fallback

What is this project?

This is a hardware information explorer that reads the SMBIOS (System Management BIOS) firmware table — a structured data blob that your BIOS or UEFI firmware fills in at every boot, describing the physical hardware it found: every memory slot, the CPU socket, the motherboard manufacturer, BIOS version, serial numbers, and more.

On Linux, the kernel exposes this table at /sys/firmware/dmi/tables/. Our C program reads and parses that binary data according to the DMTF DSP0134 specification, then presents it through both a console menu and a web interface.

On WSL2 — where the kernel may not expose the DMI tables — the web interface automatically falls back to querying the same data through Windows WMI via PowerShell interop, so you always see real hardware information from your machine.

Why we built it

We've always been curious about what actually happens the moment you press the power button — before the OS loads, before the bootloader, before anything visible on screen. The BIOS and UEFI firmware are running, silently scanning every piece of hardware and writing it all down in a structured table that the OS can later read.

That felt like a fascinating layer to explore. Most people interact with their hardware through layers of abstraction — device managers, system settings — but the SMBIOS table is as close as you can get to the firmware's raw view of the machine. Reading it in code means parsing actual binary structures, decoding bitfields, following string tables: real low-level work.

For our Operating Systems course, we wanted a project that wasn't just theoretically interesting but genuinely fun to run on your own machine — something that shows your specific hardware in a way most tools don't bother making visible.

How it works

1
BIOS / UEFI fills the SMBIOS table at boot

Before the OS loads, firmware scans all hardware and writes structured records into memory — one record per component type.

2
Linux kernel exposes the table to user-space

The kernel maps the raw binary blob to /sys/firmware/dmi/tables/DMI, making it readable by any program with the right permissions.

3
Our C parser reads and decodes the binary structures

We parse each SMBIOS structure header, follow offsets defined in the DMTF spec, decode bitfields and enum values, and extract the string table at the end of each record.

4
Django presents the data in the browser

The web interface runs the C binary, captures its output, parses it into sections, and renders it with a sakura-themed UI — section cards, a sticky sidebar, and falling cherry blossom petals.

5
Windows WMI fallback for WSL2

If the DMI tables aren't accessible (common on WSL2), the view calls powershell.exe to query Windows WMI classes and returns the same hardware data through a different path.
